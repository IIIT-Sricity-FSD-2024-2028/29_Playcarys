01 · The one rule everything else hangs off

Never build an entry fee field

Not "disabled". Not "nullable, default 0". Do not create the column. A field that does not exist cannot be set by a future you at 2am, cannot be set by a compromised admin account, and cannot be set by a well-meaning contributor who thinks it would be a nice feature.

Under the Promotion and Regulation of Online Gaming Act, 2025, a tournament becomes a banned online money game the moment a user pays a fee or stake in expectation of winning. Section 9(1): up to 3 years and ₹1 crore. The schema is your enforcement mechanism — make the illegal state unrepresentable.

Everything below follows from that one decision. Prizes come from sponsors. Entry is always free. Your rake is zero, forever — you make money from the sponsor, the venue subscription and the organisation licence, not from the players.

02 · The eligibility gate — read this before anything else

You asked to flood the catalogue with games. That is the right move, but it collides with tournaments in a way that is not obvious, so here is the finding plainly:

No embed network can give you a score

I checked every major one. GameDistribution's SDK exposes only SDK_READY, SDK_GAME_START, SDK_GAME_PAUSE and ad events — no score, no postMessage to the parent. GamePix has a ping() score method, but it transmits to GamePix's own backend, not to you. Playgama, CrazyGames, Y8 and Gamezop are all the same story — scores live with them. CrazyGames actively blocks embedding with Sitelock.

The only exception is Google GameSnacks Partner SDK, which does expose score.onChange() and game.onGameOver() to the embedding partner — but it is a gated Google partnership, not self-serve.

So: you cannot run a tournament on an embedded game. Not "it would be hard" — the data physically does not cross the iframe boundary.

The two-layer catalogue

LayerSourceVolumeCan doCannot do
Layer 1 — EmbedsGameDistribution feed, GamePix feed 200–500 in an afternoonBrowse, play, "Play Now", catalogue depth, ad revenue share Tournaments. Achievements. Carys. Leaderboards. No score crosses the frame

Add one boolean to games and the whole problem disappears:

// games table — new fields
delivery_kind:         'embed' | 'builtin' | 'hosted'
tournament_eligible:   boolean   // true ONLY when the game reports via PlayCarys SDK
achievements_eligible: boolean   // same gate
carys_eligible:        boolean   // same gate — cannot verify play, cannot pay
embed_url:             text      // null for self-hosted
catalogue_source:      'self' | 'gamedistribution' | 'gamepix'
external_id:           text      // the network's game id, for dedupe
What this buys you in the UI

The tournament creation screen's game picker filters on tournament_eligible = true. A café owner never sees a game they cannot run a tournament on, so they never hit a dead end. Meanwhile the catalogue shows all 500 games and looks like a real platform. Both things are true at once and neither lies to anyone.

Why sponsor_direct is the default

YaLLa Esports was liquidated in 2025 owing roughly $700,000 in unpaid prize money across eight tournaments, including a $200,000 prize from a 2024 LAN that was never paid. They collected sponsor money, spent it, and could not pay winners.

If the sponsor pays the winner directly, three things go away at once: you never hold money that is not yours, you have no Section 194BA obligation to deduct 30% TDS on winnings, and an unpaid prize is the sponsor's reputational problem rather than your legal one. Only move to 'platform' fulfilment when a sponsor insists and you have the money in your account first.

The trap in your current bracket code

generateBracket() assumes you decide who plays whom. But you removed rooms for multiplayer — the publisher's game does its own matchmaking now. So for any publisher-run multiplayer game, you cannot tell it "put these two specific people against each other", and a knockout bracket cannot advance.

Gate it: the bracket option only appears when game.delivery_kind = 'builtin'. For everything else, offer ladder. The code you wrote is correct — it just needs to stop being offered where it cannot work.

The format picker, in code

function availableFormats(game) {
  // R-TRN-9: no tournament on a game that cannot report a result
  if (!game.tournament_eligible) return [];

  if (game.game_mode === 'single') return ['score_attack'];

  // multiplayer
  return game.delivery_kind === 'builtin'
    ? ['bracket', 'ladder']   // we control pairing
    : ['ladder'];               // publisher controls pairing
}

05 · Fair play — the fresh-state namespace

Your instinct was right and it costs one string. A tournament run must not inherit the upgrades a player has been grinding for a month, or you are ranking spending time, not skill.

// normal play
state:{player_id}:{game_id}:main

// tournament play — thrown away when the tournament closes
state:{player_id}:{game_id}:t{tournament_id}

Same storage system, one extra key segment. On tournament entry the namespace is empty, so the game boots fresh. You do not need a second copy of the game, and you do not need to modify the game code — only the key your SDK hands it.

SDK surface for a tournament run

PlayCarys.init(apiKey, gameId)
  → PLAYCARYS_INIT_ACK { player, gameId, tournamentId, stateNamespace }

PlayCarys.loadState()          // reads the namespaced blob (empty in a tournament)
PlayCarys.saveState(blob)      // writes to the namespaced blob
PlayCarys.reportStat(k, v)     // declared keys only — distance_m, score, flips
PlayCarys.submitResult({ outcome, score, stats })
  → server: verify tournamentId is open, player is registered, attempts < max
  → write tournament_entries.best_score if better
  → recompute leaderboard rank
The cheating problem you have not solved yet

For a self-hosted single-player game there is no publisher server, so the score comes from the player's own browser. Your hosted bundles run same-origin — your own scan rules PC-SESSION-READ and PC-STORAGE-ACCESS exist because of exactly this. A player with devtools can call submitResult({score: 999999}).

Three cheap mitigations, in order of value:

  • Sanity ceiling per game. Store max_plausible_score on the game row. Anything above it is flagged, not awarded. One integer, catches almost everything.
  • Hold the top 3 for review before prizes. A tournament has a close date anyway — use it. Manual review of three runs is minutes of work and it is what makes the leaderboard credible.
  • Never award PC/Carys from an unverified single-player score. XP freely; hard currency only from reviewed tournament placement.

06 · New rules, in your R- style

RuleStatement
R-TRN-9A tournament may only be created on a game with tournament_eligible = true. Embedded games are never eligible.
R-TRN-10entry_type is always 'free'. There is no entry fee, deposit, stake or buy-in — in cash, in Carys, or in any other form.
R-TRN-11A prize pool > 0 requires a sponsor_id. Prizes are never funded from player contributions.
R-TRN-12SUM(prize_distribution.amount_minor) must equal prize_pool_minor. Enforced on save, not on display.
R-TRN-13bracket format requires game.delivery_kind = 'builtin'. Otherwise only ladder is offered.
R-TRN-14Every tournament run uses a tournament-scoped state namespace. Main-save state is never readable from inside a tournament run.
R-TRN-15A score above the game's max_plausible_score is recorded but flagged, and does not rank until a human clears it.
R-TRN-16A tournament with prize_kind != 'none' cannot move to completed until every prize_distribution row has a recorded winner.
R-TRN-17Players below min_age cannot register. Default 13.
R-TRN-18Tournament records are never deleted. A cancelled tournament keeps its entries and results as history.

07 · The sponsor report — this is the product

The thing you are actually selling

A sponsor is not buying a bracket. They are buying proof that they reached students. You already collect every number needed for this and display none of them. Build this page and you have something to charge ₹1,50,000 for. Skip it and you have a free bracket tool.

The licensing traps that catch everyone

An MIT licence does not clear someone else's trademark
  • he-is-talha/html-css-javascript-games is MIT — and contains Candy Crush, Pac-Man, Flappy Bird, Tetris and Doodle Jump clones. The MIT grant is worthless against King, Bandai Namco or The Tetris Company. Cherry-pick from this repo; do not bulk-import it.
  • platzhersh/pacman-canvas is CC0 — Pac-Man is still a Bandai Namco trademark. CC0 waives the author's rights only.
  • "8 Ball Pool" is Miniclip's brand. Eight-ball itself is public domain — build the game, call it "Pool" or "Cue Club", never "8 Ball Pool".
  • "Ludo King" is a Gametion trademark application in India (App. 3443368, Class 28). Plain "Ludo" is fine. "Carrom Pool" is Miniclip's — plain "Carrom" is fine.
  • No LICENSE file means all rights reserved, not "free to use". "It's on GitHub" is not a licence.
  • Never rip a game from another portal and self-host it. That is straightforward copyright infringement under ss.14 and 51 of the Copyright Act 1957, and the "game archive" repos on GitHub are openly redistributing infringing copies.
Two blocklists are built into the importer

It skips trademark-risky titles (Tetris, Pac-Man, 8 Ball Pool, Ludo King, Carrom Pool…) and hard-blocks anything gambling-adjacent — casino, slots, poker, rummy, teen patti, andar bahar, satta. That second list is not squeamishness: under the 2025 Act, hosting those is the offence you spent this whole document avoiding. Note it blocks "Teen Patti Gold" and "Rummy Circle" while allowing "Carrom Board" and "Pool Master".
